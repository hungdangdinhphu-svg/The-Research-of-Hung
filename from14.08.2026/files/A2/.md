## Appendix

**A.2 Formalizing the Axioms**

The Abstract's "spacing between expressions" is an evocative gloss for what Axiom A2 already defines formally as 𝑑𝕊; no further formalization of that phrase is needed beyond pointing the reader to A2. The three axioms of Section 1, however, contain several terms that require independent formal treatment: "structure," "directly on the structure," "logically equivalent," and "expressive power equivalent to that of ℝ."

Definition A.3 (Structure-Only Access / Oracle Model). Say that a function f: 𝔈 × 𝔈 → 𝑌 (for some codomain 𝑌) is computed directly on the structure of its inputs if f is computed by an algorithm that accesses A and B only through a fixed, finite set of primitive AST operations — e.g., root-label(A), left-child(A), right-child(A), is-leaf(A), leaf-value(A) — and does not call any subroutine that returns eval_σ(A′) or eval_σ(B′) for any subtree A′, B′ (including A, B themselves) as a full real- or floating-point-valued number. This is the formal content of the phrase "does not involve the explicit, full computation of eval(A) and eval(B)" in Axiom A1.

This definition is what separates the open problem from a trivial reformulation. Note carefully what it does not forbid: an algorithm satisfying Definition A.3 may still perform arithmetic on bounded fragments of the leaves (e.g., comparing exponent fields of two floating-point literals, as in floating-point filters — see A.5) as long as it never reconstructs a value that is extensionally equal to eval_σ(A) for a non-leaf A. The boundary between "structural access" and "full evaluation" is precisely the boundary the central open problem asks about, and Definition A.3 is offered as the working formalization of that boundary rather than as a claim that the boundary is unambiguous in all cases — see A.6 for the residual ambiguity.

Definition A.4 (Logical Equivalence of Relations). Two binary relations R₁, R₂ ⊆ 𝔈 × 𝔈 are logically equivalent if for all A, B ∈ 𝔈, R₁(A,B) ⟺ R₂(A,B). Axiom A1 asserts ⪯𝕊 is logically equivalent (Definition A.4) to the relation {(A,B) : eval(A) ≤ eval(B)}, i.e., they agree as extensional relations (same truth value on every pair), while remaining distinct as intensional procedures (Definition A.3 restricts how ⪯𝕊 may be computed, with no such restriction on eval(A) ≤ eval(B)). This extensional/intensional distinction is the technical core of Axiom A1 and should be stated explicitly in any formal treatment, since "logically equivalent" alone is ambiguous between the two readings.

Definition A.5 (Discriminative Power / Order Embedding). A structure (𝕊, ⪯𝕊) has discriminative power equivalent to that of ℝ (Axiom A3) if the evaluation map eval, restricted to the relevant finite-precision expression class 𝔈_𝔽 (closed expressions with 𝔽-valued leaves), is an order embedding of (𝔈_𝔽 / ~, ⪯𝕊) into (ℝ, ≤), where A ~ B ⟺ eval(A) = eval(B). Concretely: for all A, B ∈ 𝔈_𝔽, eval(A) < eval(B) ⟹ ¬⪯𝕊(B,A), and eval(A) = eval(B) ⟹ ⪯𝕊(A,B) ∧ ⪯𝕊(B,A). Equivalently, ⪯𝕊 must be a total preorder on 𝔈_𝔽 whose induced quotient order is isomorphic to the restriction of (ℝ, ≤) to {eval(A) : A ∈ 𝔈_𝔽}. This is what Axiom A3 means by 𝕊 "must support a total ordering relation with expressive power equivalent to that of ℝ" — it is an order-embedding requirement, not a cardinality or measure-theoretic requirement (a point the main text itself clarifies in the paragraph following A3, which this definition simply operationalizes).

Note on scope: because 𝔈_𝔽 is countable (a countable union, over syntactic sizes n, of finite sets of ASTs of size n over a finite alphabet with 𝔽-valued leaves, and 𝔽 itself is finite), Definition A.5 requires only a countable order embedding, not an embedding of all of ℝ. This is precisely the observation the main text makes when it distinguishes the "cardinality/countability" reading of Axiom A3 (explicitly disclaimed) from the "cost" reading (the one intended).

**A.3 Formalizing "Cost" and COST_ALL**

Section 3's COST_ALL = Cost_computation + Cost_memory/representation + Cost_khác ("other cost") is stated only descriptively. A referee will require each term to be tied to a standard complexity-theoretic or computer-architecture cost model. We give one admissible formalization; the open problem in Section 4 should be read as quantifying over the choice of cost model, subject to the constraint that the model reflect a "real-world environment and specified equipment" as the paper requires.

Definition A.6 (Cost Model). A cost model is a triple 𝑀 = (𝒜, T, S) where 𝒜 is a class of algorithms operating on a fixed machine model (e.g., a word-RAM with word size w = 64 bits, matching 𝔽; or a physical CPU with a specified instruction set and memory hierarchy), T: 𝒜 × 𝔈 × 𝔈 → ℕ is a time-cost function (e.g., number of machine instructions or clock cycles), and S: 𝒜 × 𝔈 × 𝔈 → ℕ is a space-cost function (peak bits of memory used, including any auxiliary representation of A, B beyond their AST encoding). Then, for an algorithm 𝒫 ∈ 𝒜 implementing ⪯𝕊 or 𝑑𝕊:

COST_ALL(𝒫, A, B) := T(𝒫, A, B) + S(𝒫, A, B)

(with the two terms optionally weighted by hardware-specific constants c_T, c_S > 0 to reflect the paper's "other cost," Cost_khác — e.g., energy-per-cycle vs. energy-per-bit-stored on the specified equipment; setting c_T = c_S = 1 recovers the additive form given in the main text). This turns Section 3's descriptive sum into a standard time-space cost functional, of the kind used throughout algorithm analysis and communication complexity [20]. All subsequent COST_ALL comparisons in the paper (e.g., "genuinely lower than that of the 'reduce to ℝ and then compare' approach") are then comparisons of this functional evaluated on the baseline algorithm 𝒫_baseline (full evaluation via eval_σ, then IEEE 754 comparison) versus a candidate 𝒫 satisfying Definition A.3.

Definition A.7 (Baseline Algorithm and Baseline Cost). The classical processing workflow named in the Abstract is formally the algorithm 𝒫_baseline that (i) computes v_A = eval_σ(A), v_B = eval_σ(B) by a bottom-up postorder traversal of the ASTs, using 𝔽-arithmetic at each internal node, and (ii) returns the IEEE 754 comparison v_A ≤ v_B. Its cost is:

T(𝒫_baseline, A, B) = Θ(|A| + |B|) machine words (one 𝔽-operation per internal node), S(𝒫_baseline, A, B) = Θ(1) beyond the input ASTs (only the two running scalar values need be retained during a postorder evaluation, plus a constant-size stack of depth O(depth(A)) for recursive evaluation, or Θ(depth(A)) if the traversal is implemented recursively rather than via an explicit iterative postorder — this distinction should be made explicit in any refereed cost analysis, as it affects whether S(𝒫_baseline,·) is Θ(1) or Θ(depth(A))).

This gives a precise, defensible reading of "COST_ALL of the classical procedure" that a referee can check line by line, and it exposes an asymmetry the main text does not make explicit: 𝒫_baseline is already linear in input size, so any candidate structural algorithm 𝒫 satisfying Definition A.3 must beat Θ(|A| + |B|) — it cannot merely match it — for the central open problem (Section 4) to have a nontrivial affirmative answer in the asymptotic sense. A nontrivial affirmative answer could instead be sought in the constant-factor sense (smaller leading constant, same asymptotic order) or in the amortized/incremental sense (Appendix A.7); the paper does not currently distinguish these three possible senses of "strictly less," and doing so is itself part of sharpening the open problem.

**A.4 The Comparison-Based Lower Bound and Why It Does Not Resolve the Open Problem**

This section supplies the missing "full mathematical/information-theoretic analysis" the paper's Section 4.1 gestures at but does not carry out. It is included because a referee working in algorithms or information theory will immediately ask "does a decision-tree argument already settle this?" — and the answer is subtle enough to need a careful statement.

Proposition A.1 (Trivial Information-Theoretic Lower Bound, and why it is not the relevant one). Consider N closed, distinct-valued expressions A₁, …, A_N ∈ 𝔈_𝔽 (no shared subexpressions, adversarial values) to be totally ordered (Major Issue 1's setting, generalized to N expressions as in the paper's opening framing). Under the comparison-based model — where the only primitive operation permitted is a binary comparison oracle C(i,j) ↦ 1{eval(A_i) ≤ eval(A_j)} treated as a black box of unit cost — any correct sorting algorithm requires Ω(N log N) calls to C in the worst case [21, Ch. 5.3]. This is the standard decision-tree/counting bound: there are N! possible total orders, each comparison has 2 outcomes, so a decision tree of depth d distinguishes at most 2^d orders, forcing d ≥ log₂(N!) = Ω(N log N).

Why Proposition A.1 does not answer the central open problem: Proposition A.1 lower-bounds the number of pairwise-comparison calls, treating each call to ⪯𝕊(A_i, A_j) as unit cost. It says nothing about the cost of implementing a single call to ⪯𝕊 — which is exactly what Axioms A1–A3 and COST_ALL (Definition A.6) are about. The central open problem is a statement about the internal cost structure of one evaluation of ⪯𝕊(A,B), not about the number of such evaluations needed to sort or totally order a collection. These are orthogonal axes: Major Issue 1/2 could in principle be resolved with COST_ALL(⪯𝕊, A, B) = o(|A| + |B|) (a genuine win over Definition A.7's baseline) while the number of pairwise calls needed to fully order N expressions remains Ω(N log N) regardless, exactly as in ordinary comparison sorting with cheap comparators. Conversely, no structural speed-up of ⪯𝕊 can push total-order construction below Ω(N log N) comparisons, though it can push it below Ω(N log N) · Θ(|A|+|B|) in wall-clock terms. This clarifies a possible source of confusion in the paper: A3's requirement of a "total order... equivalent to that of ℝ" concerns the output structure (Definition A.5), while COST_ALL concerns the cost of the relation, not the cost of sorting with it; Proposition A.1 bounds a third, distinct quantity. A rigorous version of the paper should state this separation explicitly, since conflating them would make the open problem appear to already have a known negative answer when it does not.

Proposition A.2 (An honest, non-trivial partial lower bound: communication complexity of ⪯𝕊 itself). Suppose 𝕊-side evaluation of ⪯𝕊(A,B) is required to be representation-oblivious to shared structure — i.e., the algorithm may inspect A and B but the cost model charges Θ(1) per AST node visited (Definition A.6 specializes T to node-visits). Then, by a straightforward adversary/fooling-set argument analogous to those used in communication complexity [19, 20]: for the subclass of expressions that are balanced binary trees representing degree-2^k polynomials in disjoint variables with adversarially chosen finite-precision coefficients, any algorithm satisfying Definition A.3 that is guaranteed correct on every assignment σ must, in the worst case over σ, inspect Ω(min(|A|,|B|)) leaves of the smaller tree — because for any strict subset of leaves left uninspected, an adversary can perturb an uninspected coefficient to flip the sign of eval_σ(A) − eval_σ(B) without changing anything the algorithm observed, using the fact that {+,−,×,÷} expressions of size n can realize value swings of magnitude exceeding any fixed threshold by perturbing a single leaf (since × and ÷ allow multiplicative blow-up). This gives Ω(min(|A|,|B|)) as an unconditional worst-case lower bound on T(𝒫, A, B) for any correct 𝒫 in this cost model, matching Definition A.7's baseline up to constants. In other words: for the fully adversarial, all-σ-correct version of Major Issue 1, no asymptotic (order-of-growth) speed-up over the baseline is possible in the worst case, under the node-visit cost model. This is consistent with, and gives a rigorous instance of, the paper's own informal observation that "if 𝕊 is simply forced to reduce to ℝ before a comparison can be made, it reverts exactly to the classical processing workflow" (Section 1) — Proposition A.2 shows that for the adversarial worst case, this reversion is not merely a risk but a provable necessity under the stated cost model.

This is important for correctly scoping the open problem: Proposition A.2 shows the open problem, read in the strongest ("worst-case over all σ and all adversarial expressions, node-visit cost, asymptotic order") sense, has a negative answer for Major Issue 1 — precisely because the paper's own exclusion of transcendental functions (to preserve decidability, via Richardson's theorem [1]) does not also exclude adversarial value-sensitivity of every leaf, which is what Proposition A.2 exploits. The genuinely open content of Major Issue 1 therefore lies in the gap between this worst-case impossibility and the average-case, structured-input, or approximate/probabilistic regimes — exactly the regimes in which the paper's own cited precedents (Shewchuk [4], Yap [5, 6]) operate, and exactly why those precedents are precedents for a relaxed version of A1–A3 rather than resolutions of the axioms as literally stated. A rigorous version of Section 4.1(ii) should state this explicitly: the open problem is open in the average-case / adaptive-cost regime, and (by Proposition A.2) essentially closed in the negative in the strict worst-case regime, for Major Issue 1. This qualification does not affect Major Issue 2, whose fixed sum-of-products structure changes the adversary argument (see A.5.3).

**A.5 Formal Grounding of the Cited Precedents**

A.5.1 Interval Arithmetic and Adaptive Precision (Shewchuk, Yap)

Interval arithmetic [7, 8] represents each real quantity by a pair (a,b) ∈ 𝔽 × 𝔽 with a ≤ b guaranteed to contain the true value, and propagates operations via ⊙_interval: ([a₁,b₁], [a₂,b₂]) ↦ [min/max combinations], with the IEEE 1788-2015 standard [23] formalizing directed-rounding semantics. Floating-point filters, as used by Shewchuk [4] and surveyed by Yap and collaborators [5, 6], compute a fast, low-precision (native 𝔽) approximation of eval(A) − eval(B) together with a certified error bound; the sign is returned immediately if the approximation's magnitude exceeds the error bound (the filter succeeds), and only otherwise does the algorithm fall back to exact/arbitrary-precision arithmetic (the filter fails, requiring the equivalent of full eval). Formally, this is an instance of Definition A.3's structural-access model in a relaxed sense: the filter step accesses only bounded-precision partial evaluations (Θ(1) machine words per node, not the exact value), so — in the terminology of Definition A.6 — it achieves T(𝒫,A,B) = Θ(|A|+|B|) in the filter-success case, which is the same asymptotic order as the baseline (Definition A.7) but with a much smaller constant (native hardware floating-point ops vs. arbitrary-precision bignum ops), and it degrades to the baseline's cost (or worse) in the filter-failure case. This is precisely why the main text is careful to say these techniques achieve A1 "at a lower average cost" and "do not necessarily satisfy all three axioms... in every case": they give constant-factor, input-dependent (adaptive) savings, not the asymptotic, worst-case, all-σ savings that Axiom A3's literal reading (Definition A.5, combined with Proposition A.2) would require in the adversarial regime. This is the precise technical content behind the informal phrase "adaptive" in Shewchuk's title and in the main text.

A.5.2 Johnson–Lindenstrauss / Random Projection

The Johnson–Lindenstrauss lemma [9], with the widely used explicit constant due to Frankl–Maehara [10] and simplified proofs by Dasgupta–Gupta [11] and others, states: for any 0 < ε < 1 and any finite set X ⊂ ℝ^d of n points, there exists a linear map f: ℝ^d → ℝ^k with k = O(ε⁻² log n) such that for all x, y ∈ X,

(1 − ε)‖x − y‖² ≤ ‖f(x) − f(y)‖² ≤ (1 + ε)‖x − y‖².

Random Gaussian or database-friendly sign projections [15] achieve this with high probability. In the terms of this paper, this is a candidate 𝑑𝕊 (Axiom A2) for Major Issue 2's inner-product setting: computing ⟨f(u), f(v)⟩ in ℝ^k costs O(k) = O(ε⁻² log n) rather than O(n) for the original ⟨u,v⟩ = Σᵢ uᵢvᵢ, a genuine asymptotic win when n ≫ log n / ε². However — and this is the precise sense in which JL "does not satisfy A3" as the main text states — the JL guarantee is (a) probabilistic (holds with probability ≥ 1 − 1/n² per pair, via a union bound over the O(n²) pairs, not with certainty [11, 25]), and (b) an approximate isometry (multiplicative distortion factor (1±ε), not exact equality), so the induced relation "‖f(u)−f(w)‖ ≤ ‖f(v)−f(w)‖" is not logically equivalent (Definition A.4) to the exact relation eval(A) ≤ eval(B) — it can disagree on pairs whose true distance differs by less than the O(ε) distortion margin. This is exactly the gap Axiom A3 (via Definition A.5, which demands an exact order embedding) forbids, formalizing the paper's remark that "these are probabilistic or approximate solutions that do not satisfy A3 (requiring an exact total order without error)."

A.5.3 Maximum Inner Product Search (MIPS) and Locality-Sensitive Hashing

Locality-Sensitive Hashing [12] and its extension to the asymmetric, inner-product setting (ALSH/MIPS) by Shrivastava and Li [13], later refined by Neyshabur and Srebro [14], solve the approximate nearest/furthest inner-product neighbor problem in sublinear query time (sublinear in the database size N, not in the vector dimension n) by constructing hash families h such that Pr[h(u) = h(v)] is a monotonic function of ⟨u,v⟩ after an asymmetric transformation of query and database vectors. This targets a different (though related) problem from the one posed in Major Issue 2: LSH/MIPS accelerates search (finding the argmax over a large collection) rather than pairwise comparison (deciding ⪯𝕊(A,B) for two given expressions), and — like JL — its correctness guarantee is probabilistic, not exact. It is cited correctly in the main text as evidence that "the specific sum-of-products structure" of Major Issue 2 is more tractable than the unconstrained case, since these methods exploit exactly the fixed bilinear form Σᵢ uᵢvᵢ, a structural regularity absent from arbitrary {+,−,×,÷} expressions (Major Issue 1) and which blocks the adversarial-leaf argument of Proposition A.2 in its strongest form — because in the inner-product setting an adversary is constrained to perturbations of the form δ(uᵢvᵢ), not an arbitrary recursive composition of {+,−,×,÷}, which caps how much a single-coordinate perturbation can move ⟨u,v⟩ relative to ‖u‖‖v‖ (via Cauchy–Schwarz), unlike the unbounded multiplicative blow-up available in general expression trees.

**A.6 Residual Ambiguity: What Definition A.3 Does Not Settle**

In the interest of accuracy, this Appendix does not claim to have fully closed the definitional gap the paper is built on. Definition A.3 draws the structural/non-structural line at whether a subroutine call returns a value extensionally equal to eval_σ of a subtree. Two edge cases remain genuinely ambiguous, and a rigorous treatment should flag rather than paper over them:

(i) Partial evaluation. An algorithm that evaluates eval_σ(A) to k bits of precision (k fixed, independent of the adversary) and no further is not evaluating "the explicit, full computation of eval(A)" in the paper's phrase, yet it is also not purely structural in an intuitive sense — this is exactly the regime floating-point filters (A.5.1) occupy, and is why they are offered as partial, not full, precedent.

(ii) Structure-dependent short-circuiting. An algorithm may inspect only the root operator of A and B (e.g., "A is syntactically A₁ + A₂ with A₁ ⪯𝕊 0 and A₂ ⪯𝕊 0, hence A ⪯𝕊 0 without inspecting values") — this is structural by Definition A.3, but its worst-case cost savings depend entirely on how often such syntactic patterns occur in the input distribution, tying the open problem's resolution to a distributional assumption on 𝔈 that neither the main text nor Definition A.6 currently specifies. Any complete resolution of the central open problem (Section 4) will need to fix this distributional assumption (worst-case vs. average-case vs. a specified input model) as part of the problem statement, in addition to fixing the cost model (Definition A.6) and the sense of "strictly less" (asymptotic order, constant factor, or amortized — Appendix A.3, A.7).

**A.7 A Sharpened Restatement of the Central Open Problem**

Combining A.3–A.6, the central open problem (Section 4) can be restated with all quantifiers made explicit, which is the form a peer reviewer will expect:

Open Problem (sharpened). Fix a cost model 𝑀 = (𝒜, T, S) per Definition A.6 on a specified machine (word-RAM or named physical hardware), an input regime ℛ ∈ {worst-case, average-case under a specified distribution 𝒟 on 𝔈_𝔽, amortized over a query sequence}, and a comparison sense κ ∈ {asymptotic order, constant-factor at fixed order, amortized-per-query}. Does there exist an algorithm 𝒫 satisfying the structural-access constraint of Definition A.3, computing a relation ⪯𝕊 logically equivalent (Definition A.4) to eval(A) ≤ eval(B) and possessing discriminative power equivalent to ℝ on 𝔈_𝔽 (Definition A.5), such that COST_ALL(𝒫, A, B) is strictly less than COST_ALL(𝒫_baseline, A, B) (Definition A.7) in the sense κ, under regime ℛ?

By Proposition A.2, the answer is no for ℛ = worst-case and κ = asymptotic order, for Major Issue 1 (general {+,−,×,÷} expressions), under the node-visit cost model. By A.5.1–A.5.2, the answer is conditionally yes (constant-factor sense κ, adaptive/average-case regime ℛ) for restricted subclasses via floating-point filters, and yes in an approximate/probabilistic relaxation of Axiom A3 for Major Issue 2 via JL/MIPS. The genuinely open region of the problem — consistent with, and now made precise from, the paper's own Section 4.2 conclusion — is: (a) Major Issue 1 under ℛ = average-case with a natural (not adversarially chosen) distribution 𝒟 on expressions, where no matching lower bound analogous to Proposition A.2 is currently known to the author; and (b) Major Issue 2 under the exact (non-probabilistic) reading of Axiom A3, where JL/MIPS-type methods are known to be inapplicable as stated (A.5.2, A.5.3) and no alternative exact structural algorithm beating Θ(n) is known to exist or not exist.
